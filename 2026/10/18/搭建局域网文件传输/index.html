本次使用成熟的第三方库 lw-share 来实现局域网文件传输功能。

环境准备

安装 Node v20（宝塔方式）

由于我的 Ubuntu 系统默认 Node 为 v14（npm 6.x），而 lw-share 要求 Node ≥ 18，需要单独使用 Node v20 来运行 lw-share，避免影响系统其他服务。

通过宝塔面板 → 软件商店 → Node.js 版本管理器 → 安装 Node v20.20.2，安装路径通常为：

如果不确定宝塔安装的node20的路径，也可以先通过把node20版本设置为默认版本，然后再查看node路径。

验证node20是否安装成功

关键点：lw-share 的 systemd 服务将写死使用此路径的 node 二进制，与系统默认 Node 版本完全解耦。

上传文件名乱码问题

问题现象：

  • 上传中文名文件后，服务器 /root/lw-share-data/share/ 目录中文件名显示为乱码（如 ååäº¬è…）
  • 文件内容正常，仅文件名异常
  • 下载到 Windows 后文件名仍为乱码

原因分析：
lw-share 在解析 multipart 上传时，将 UTF-8 编码的文件名按 Latin-1 单字节解码后直接落盘，导致 mojibake（编码错乱）。这是 lw-share 上游的已知行为，不修改源码的情况下需要从外部修复。

修复方案

使用外部脚本还原文件名。

创建手动批量修复脚本 /root/fix-lwshare-names.mjs

手动执行修复

自动监听修复

安装 inotify-tools

创建监听脚本 /root/lwshare-watcher.sh

为 /root/lwshare-watcher.sh 添加执行权限

创建服务文件 /etc/systemd/system/lwShareFix.service

启用修复服务

此后每次上传文件，inotifywait 会在文件写入完成后自动触发修复脚本，将乱码文件名还原为中文。

注意事项与踩坑记录

问题说明
Node 版本冲突系统默认 Node14 不能运行 lw-share，必须在 service 中写死 Node20 绝对路径
PATH 未包含 npm bin直接执行 lw-share 命令找不到，需用 npx 或绝对路径调用
宝塔安全组宝塔面板安全规则 + 系统 ufw 双层放行，缺一不可
切回 Node14 不影响service 写死 v20.20.2 路径，与宝塔默认版本切换无关
乱码不可逆条件若文件名显示为 ??? 而非 åå…，说明字节已丢失，无法还原
端口选择60889 为自定义端口，避免与常见服务（3000/8080）冲突
工作目录权限/root/lw-share-data 需确保运行用户（root）有读写权限
